== Project Timeline

=== The Genesis Problem (2024)

Nix was designed for flakes — composable, reproducible inputs with
cryptographic guarantees. But the ecosystem diverged. Non-flake workflows
became dominant. Tools that should have been simple became complex.

Meanwhile, teams using esoteric VCS (DARCS, Pijul, Fossil) faced a gap:
their tools had no native concept of pinning, Merkle-ized hashes, or
reproducible fetch. Integrating these sources into production Nix pipelines
required manual, error-prone work.

=== Foundation (2025-12)

Nixtamal was created to bridge this gap:

* **KDL manifest** — human-readable input declarations
* **Lockfile (JSON)** — reproducible, verifiable source pins
* **VCS abstraction** — DARCS, Pijul, Fossil, Git in one interface
* **Merkle-ized hashing** — SHA-256, SHA-512, BLAKE3
* **Flake integration** — esoteric sources become flake inputs

=== Phase 1: Core Platform (2025-12 — 2026-01)

* Type system: Input, Lockfile, Manifest
* KDL codec for configuration
* Concurrent prefetching with Eio (OCaml 5)
* Git, DARCS, Pijul VCS support
* Basic CLI: lock, refresh, show
* Flake support (flake.nix, flake.lock)

=== Phase 2: Production Hardening (2026-02 — 2026-04)

* **Security**: URI validation, scheme whitelist, path traversal detection
* **Schema versioning**: Upgrade paths with backup/rollback
* **Fossil VCS**: Complete implementation
* **Lockfile auto-creation**: Graceful handling of missing files
* **Test coverage**: bisect_ppx infrastructure, CI pipeline
* **Cmdliner 2.x**: Modern CLI framework

=== Phase 3: Full Feature Set (2026-10)

* **Blueprint system**: Project scaffolding
* **Garbage collection**: Input lifecycle management
* **Patch vendoring**: Offline stability
* **TUI improvements**: Progress display, fetch status
* **Mirror support**: TUNA fallback for resilience
* **Schema 1.5.0**: Extended manifest capabilities

=== Documentation & Community (2026-10)

* Community-focused AsciiDoc documentation
* nixtamal.tech website preparation
* Discord community server (upcoming)
* Professional positioning

== Lessons Learned

=== Technical

* **Type systems catch bugs** — OCaml's strict typing prevented entire
  classes of errors
* **Security is not optional** — URI validation, path traversal detection
* **Schema versioning pays off** — upgrade paths prevent lock-in
* **Concurrency is hard** — Eio helps, but requires careful design

=== Design

* **Composability beats abstraction** — simple, composable interfaces
  outperform complex, layered ones
* **Reproducibility is the product** — pinning, hashing, verification
* **VCS-native semantics matter** — don't wrap DARCS in a Git-shaped box
* **KDL was the right choice** — readability without whitespace hell

=== Community

* **Professional governance wins** — clear leadership, transparent roadmap
* **Documentation is product** — help people ship, not read manifestos
* **Accessibility drives adoption** — Discord, website, clear guides
* **Choose your audience** — production teams need different things than
  hobbyists

== The Future

Nixtamal aims to:

. **Be the standard bridge** for esoteric VCS in production Nix
. **Deepen flake integration** — native input composition
. **Expand VCS support** — more esoteric tools, same guarantees
. **Build the community** — nixtamal.tech, Discord, contributions
. **Maintain reproducibility** — the contract is non-negotiable

The composable future is here. Let's build it together.

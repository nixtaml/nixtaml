=== Using Nixtamal in Flake Projects

[source,nix]
----
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    nixtamal.url = "github:CrashOverBurn/nixtamal";
  };

  outputs = { self, nixpkgs, nixtamal }:
    let
      system = "x86_64-linux";
      pkgs = nixpkgs.legacyPackages.${system};
    in {
      packages.${system}.default = nixtamal.packages.${system}.default;

      devShells.${system}.default = pkgs.mkShell {
        buildInputs = [ nixtamal.packages.${system}.default ];
      };
    };
}
----

=== Bridging Esoteric VCS into Flake Projects

The core value: DARCS/Pijul/Fossil sources become flake inputs.

[source,kdl]
----
# manifest.kdl
inputs {
    my-darcs-research {
        darcs {
            repository "https://research.example.com/formal-methods"
            patch "sha256-abc123..."
        }
        hash algorithm=SHA-256
        fresh-cmd {
            $ darcs log --last 1 --xml-output | grep -o 'hash="[^"]*"'
        }
    }

    my-pijul-tool {
        pijul {
            repository "https://code.example.com/pijul-tool"
            channel "main"
        }
        hash algorithm=BLAKE3
    }
}
----

[source,bash]
----
# Lock these sources with Merkle hashes
nixtamal lock

# Generates lock.json with content-addressed pins
# Now they're reproducible flake inputs
----

== Building for Similar Systems

=== Flake Input Pinning Patterns

How to pin non-Git sources in flake projects:

[source,nix]
----
# Pattern 1: Direct flake input (Git only)
inputs.mydep.url = "github:user/repo/v1.0.0";

# Pattern 2: Via Nixtamal (any VCS)
# Use nixtamal.lock, reference in flake
inputs.nixtamal.url = "github:CrashOverBurn/nixtamal";
# Then use nixtamal.lib to consume locked sources

# Pattern 3: Fixed-output derivation
# Wrap fetcher in mkDerivation with outputHash
----

=== Git Submodule Alternatives

[cols="2,3"]
|===
| Git Submodule | Flake Input + Nixtamal

| `git submodule add <url>`
| `inputs.<name>.url = "<url>"` or `nixtamal lock`

| Manual version tracking
| `flake.lock` / `lock.json` automatic

| Nested repository complexity
| Flat input graph

| Git-only
| Any VCS (via Nixtamal)
|===

=== Lockfile Management Across Tools

[cols="2,2,2,2"]
|===
| Tool | Lockfile | VCS Support | Merkle Hashes

| Nixtamal
| `lock.json`
| Git, DARCS, Pijul, Fossil
| SHA-256, SHA-512, BLAKE3

| Flakes
| `flake.lock`
| Git only
| SHA-256

| niv
| `nix/sources.json`
| Git, tarball
| SHA-256

| npins
| `nix/sources.nix`
| Git, tarball
| SHA-256
|===

=== Migration from Other Tools

[source,bash]
----
# From manual pinning
# 1. Create manifest.kdl
# 2. Run nixtamal lock
# 3. Verify lock.json hashes

# From flake.lock (Git inputs)
# 1. Import Git inputs to manifest.kdl
# 2. Add esoteric VCS inputs
# 3. Run nixtamal lock

# From niv / npins
# 1. Convert sources to manifest.kdl
# 2. Run nixtamal lock
# 3. Verify reproducibility
----

=== Running Tests

[source,bash]
----
# All tests
dune runtest

# With coverage
BISECT_ENABLE=YES dune runtest --instrument-with bisect_ppx --force

# Coverage report
bisect-ppx-report summary --coverage-path _build/default/test
----

=== Writing Tests

[source,ocaml]
----
let test_merkle_hash =
  Alcotest.test_case "Merkle hash verification" `Quick @@ fun () ->
    let expected = "sha256-abc123..." in
    let actual = compute_merkle_hash input in
    Alcotest.(check string) "hash matches" expected actual
----
